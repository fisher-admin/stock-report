# 系统架构与发布边界

## 1. 总体结构

本系统是 A 股多头选股与研究平台，分为本机计算和 GitHub 发布两部分。所有需要行情、财务、公告、历史推荐或 AI 原始文本的数据工作均在本机完成。GitHub 只保存可公开的代码、测试、说明和结果摘要。

```text
本机数据源
  ├─ 行情与交易日历
  ├─ 财务与公告
  ├─ 推荐数据库与历史快照
  └─ AI 证据与风险标签
          │
          ▼
本机研究与选股
  ├─ 时点股票池与数据完整性检查
  ├─ 短线三组影子组合
  ├─ 公告事件质量策略
  ├─ 收益结算、成本与基准
  └─ 晋级/停止规则
          │
          ▼
发布闸门
  ├─ 评价合同校验
  ├─ 未来数据、代理数据与异常收益检查
  ├─ 删除逐股历史及原始 AI 文件
  └─ 公开结果白名单审计
          │
          ▼
GitHub
  ├─ 架构、源代码、测试与说明
  └─ Pages：当前候选、组合绩效、运行健康和研究结论
```

## 2. 选股双轨

短线轨固定保留三组前瞻观察组合：完整 v4.3 对照组、限制行业集中度的 Top15 组，以及不使用筹码代理值的 v4.4 五类等权组。三组均以 T 日收盘后形成信号、T+1 开盘成交、持有 5 日为主口径，并同时计算基础和压力成本。

中期轨为 `event_quality_drift_v1`。它只处理新公告，按当时可见的业绩变化、连续改善、质量和估值保护评分，在下一交易日开盘后进入观察，20 日为主要持有期。AI 只整理证据和标注风险，不能改变排名、增加或删除候选。

## 3. 评价与治理

- 缺价记录使用“待结算”或“数据缺失”，收益保持为空，禁止用 -100% 代替。
- 历史股票池按当日上市、ST、停牌、退市和板块状态恢复。
- 代理筹码不得进入回测、因子评价或生产排序。
- 策略名称和版本不可变；失败版本归档，不在同一验证样本上反复调权。
- 流程是否正常与策略是否有效分别展示。
- 在样本量、收益、超额收益、风险和稳定性门槛全部通过前，输出只作观察。

## 4. 公开数据合同

公开结果的唯一清单是 `config/public-result-allowlist.txt`。允许公开的是当前候选结果、组合级收益、回撤、归因、运行状态和研究结论。以下内容禁止进入 GitHub：

- 本机数据库、Parquet、CSV 和缓存；
- 历史逐股推荐及完整收益明细；
- 原始 AI 分析、提示词响应和未来日期回填记录；
- 全量行情、财务、公告和历史股票池；
- 本机绝对路径、账号凭据和私密配置。

发布脚本先在本机生成完整内部结果，再生成公开摘要。合同校验通过后，边界检查器删除本机明细，并逐个核对剩余数据文件是否在白名单内。审计失败时不会提交或推送。

## 5. 目录说明

- `system/src/orchestrator/`：股票池、双轨策略、推荐仓、评价合同与发布控制
- `system/src/factor_factory/`：时点股票池、因子面板与正式因子审计
- `system/src/stock_analyzer/`：基准选股与回测适配层
- `system/tests/`：关键流程、数据完整性和策略行为测试
- `assets/`：公开页面的数据模型与渲染代码
- `data/latest/`：GitHub Pages 使用的最新结果摘要

仓库中的 `system/` 是可公开的核心代码快照；运行所需的数据、凭据和机器配置不包含在仓库内。
