- 前提: `factor_factory/contracts/` 已落库(含 R-3 四条收紧), 自检/单测全绿(见同目录《契约层休眠落库.md》)

## 1. 直通开关方案

**三态开关, 每个消费点独立**, 缺省即现行为——保证"不切=不受扰":

| 态 | 语义 | 输出影响 |
|---|---|---|
| `off`(默认) | 契约层完全不参与, 消费点走现行取数代码 | 零 |
| `shadow` | 双跑: 现行取数照旧产出, 契约层并行取同一批数据, 帧级对账+健康度落 manifest, 差异只记录不拦截 | 零(只多一份 shadow manifest) |
| `enforce` | 消费点读契约层输出(FetchMeta/失败通道显式), 现行取数代码停用 | 全量 |

- 载体: 环境变量 `FF_CONTRACTS_MODE_<消费点ID>`(如 `FF_CONTRACTS_MODE_PEAD_INGEST`), 未设置=off; 禁止全局单开关(防一把梭)。
- 实现: 下批次新增 `contracts/switch.py` 薄适配层, 签名建议:
  `resolve_mode(consumer_id: str) -> Literal["off","shadow","enforce"]` + `shadow_compare(df_legacy, rows_by_key, meta, out_manifest) -> ShadowReport`(帧级: 键集等值/行数/价格 1e-4/单位换算后全等; 报告含契约拒绝率)。
- 铁律继承: 切换本身不改契约层代码; 每个消费点的 enforce 切换=**单独一个 commit**, 且 shadow 与 enforce 不同 commit。

## 2. 候选消费点(建议顺序)

1. **PEAD 预告摄取**(B-5 已批准, Wave1 首项): `ingest_pead_preannounce.py` → `YjygDatacenterFetcher`(27 命名键契约+PIT anchor), 与 PIT 店双写周并轨。
2. **名称/股票池快照**: stock_basic 消费点 → `SecurityMetaTushareFetcher`+`reconcile_names`(R-3.4 归一化后 5530 股 0 残差, 已 live 实证)。
3. **研究面板日线重拉/回补**(B-6 31 日洞回补同型): → `DailyTushareFetcher` 主 + `DailyAkshareSinaFetcher` 对账(live 实证 max_rel_diff=0.0)。
4. **19:30 生产管线日线取数**(最后切): 需 P-2 EM 观察结论落定(EM 死则 sina 正名对账主源), 且前三点 enforce 稳定 ≥1 周。

## 3. 切换验证步骤(每消费点逐一过, 不许跳)

1. **前置绿**: `cd factor_factory && venv/python -m contracts.tests.test_contracts`(54 断言)+`python -m contracts`(离线自检)双 exit 0。
2. **live 自检绿**(非交易时段): `python -m contracts --live` exit 0, 无 dead source。
3. **shadow ≥3 个交易日**: 开关拨 shadow, 每日核 ShadowReport: 键集/行数/1e-4 对账 0 breach; **契约拒绝率>0 的行逐条人工分类**(真脏数据=契约立功; 契约过紧=修契约再回到步骤 1)。
4. **enforce 切换**: 单 commit, 只在周五收盘后或周末落地; 当日跑一次 live 自检。
5. **生产观察**: 19:30 管线绿灯+run_manifest 无 critical, 连续 2 个交易日(同 P-1 判据)。
6. **健康度接告警**: `assess_source_health` 的 degraded/dead WARN 接入现有 Discord pipeline alert(R-3.3 阈值默认 ok 率 50%)。

## 4. 回滚

- shadow/enforce 任一步异常: **开关拨回 off 即回滚**(不需要 revert 代码); enforce commit 本身可单独 `git revert`。
- 契约层包整体回滚: 删除 `factor_factory/contracts/`(无生产 import, 删除无副作用)。

## 5. 已知边界(实施前必读)

- EM 通道(push2his)本机间歇拒绝(spike3 发现 1, P-2 观察至约 07-16): shadow 期禁用 EM(`--em` 不开), 待 P-2 结论。
- sina 日线无 pre_close(R-3.1 capability=unavailable): 涨跌停带不变式在该源不可评估——enforce 到依赖 pre_close 的消费点必须以 tushare 为主源。
- 新浪日历尾部 2026Q4 起进入 <90 天护栏窗(spike3 发现 4): W1-6 日历 provider 需先定降级路径, 不阻塞 1~3 号消费点。
