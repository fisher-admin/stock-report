```text

  → Epic B 既有四影子继续积累（已在跑，勿中断）

```

## 4. 目标架构与晋级合同

### 4.1 原则

1. 一条冻结生产对照 + 可控影子实验；禁止偷偷改对照  
2. 研究只写 shadow/ledger  
3. AI 只解释；硬升降档仅版本冻结的规则  
4. 评估口径唯一（可成交盒子）  
5. 未过门永久观察；公开诚实  

### 4.2 生命周期用语（修订）

```text
research → shadow → verified_observe（已验证观察策略） → retired
```

- **禁止** 使用易被理解为可交易的 `active` 作为对外叙事（代码枚举迁移在 Epic A 处理；对外文案一律“观察/已验证观察”）。  
- 即使 `verified_observe`，**execution_authority 仍为 observe_only_no_auto_order**。  

### 4.3 统一评估协议

```text
信号: T 日收盘后
入场: T+1 开盘（open_qfq）
涨停/停牌: 跳过并计数
成本: 0.30% 基础 / 0.50% 压力往返
基准: 全 A 可交易等权
缺失价: null + 待结算/数据缺失；禁止 -100% 或 0 伪收益
代理: forbidden
AI: 不计入选股收益
```

| 轨道 | 用途 |
|------|------|
| verify C2C | 诊断 only |
| short_track / 事件组合盯市 | **晋级唯一依据** |

### 4.4 晋级门槛

#### 4.4.1 短线（与 `shadow_portfolio_evaluator.py` 对齐）

| 条件 | 阈值（现网常量） |
|------|------------------|
| 验证起点 | 各策略 **自身** 冻结日；既有三组为 `20260811`；**v45 为首次成功输出日** |
| 新增成熟交易日 | ≥ **60**（`MIN_NEW_TRADE_DAYS`） |
| 扣成本净绝对收益 | **> 0** |

#### 4.4.2 中期事件（收益门 + **2026 完整性门**）

##### A. 与现网评价器已对齐的收益/结构门

| 条件 | 阈值（现网常量） |
|------|------------------|
| 有效公告事件 | ≥ **100** |
| 样本跨度 | ≥ **12** 个月 |
| 研究段 | 2021–2024（不进晋级主证据） |
| 冻结验证段 | **2025 全年**（`PROMOTION_START_DATE=20250101` 起的 2025 段） |
| 最终历史检验**信号**窗口 | 信号日 ∈ **[20260101, 20261231]**；`FINAL_HISTORY_END_DATE=20261231` 为允许进入最终检验的 **最后信号日期**（固定，不得随“今天”延长） |
| 2025 净绝对收益 | **> 0** |
| 2025 净超额 | **> 0** |

| 2026 净超额 | **> 0** |
| 2026 最大回撤 | **≤ 12%** |

| Top5 个股贡献 | ≤ **50%** |

| 辅助持有 40 日 | 仅诊断，不替代 20 日主门槛 |

##### B. 2026 完整性门槛（方案 v1.3 关闭；**v1.4 实施约束**）

| 门名称 | 判定依据（Codex 终审约束） |
|--------|----------------------------|
| `final_2026_signal_window_complete` | 以 **交易日历** + **独立公告采集覆盖记录** 为准；**禁止**用 ledger 最后一条候选信号日代替。无公告交易日也必须证明采集任务成功、源覆盖完整、无缺失日 |
| `final_2026_settlement_complete` | 覆盖所有 **应进入主证据** 的事件（`is_selected` 且 `revision_chain_complete`，信号日在窗内）；**禁止**把未结算事件改标 `auxiliary_only` 来绕开 |
| `final_2026_not_before_calendar_close` | `evaluation_as_of` ≥ 最后一个 2026 交易信号的 **exit_20d**（进入 2027 后才可能为真） |

**硬性语义：**

1. `FINAL_HISTORY_END_DATE=20261231` = 最后允许 **信号日**。  
2. 完整性门未过 → 即使收益门全绿也只能 `observe_only`。  
3. 无 `completeness_context` → **fail-closed**（三门全失败）。  
4. 回归：部分 2026 日历/覆盖/结算 → 绝不能 `all_gates_pass`。

## 5. 策略与因子方案

### 5.1 生产对照：完全冻结

- 不改 hard_filters、权重、TopN、行业 cap、筹码依赖合同  
- 真实筹码缺失：按 **v43 原合同** fail 或输出 **明确 degraded 且不可进入晋级样本** 的结果  
- **禁止** 全局将筹码权重改 0 后仍使用同一 `strategy_id/version` 冒充对照  

### 5.2 既有影子：继续积累

| 身份 | 要点 |
|------|------|
| top15 | 原排名截 15 + 行业最多 3 |
| v44_balanced | 五组各 20%、不读筹码、Top20、PIT 完整输入 |
| event | 日新公告；无合格事件时诚实空结果 |

### 5.3 新建：`prebreakout_v45_cross_sectional`（固定实验——无任选项）

#### 5.3.1 实验命题（单一变量）

> 在 **与 v44 完全相同** 的股票池、原始特征、组定义、组权重、TopN、持有与成本下，  
> **仅将组内截面处理** 从 v44 现有实现，替换为 §5.3.4 固定流程，  
> 是否改善 §4.4.1 合同下的风险调整后结果？

**主比较：** `v45` vs `v44`  
**辅助基准：** `v43_control`（不可当作“从四者中选优”的池子）

#### 5.3.2 身份与元数据（冻结）

| 字段 | 冻结值 |
|------|--------|
| strategy_id | `prebreakout_v45_cross_sectional` |
| 继承 | 复用 v44 的 `factor_formula_version=2026-08-11.1` 原始特征与组名 |
| 截面处理版本 | `cs_pipeline=v45.1`（本文件 §5.3.4；写入 config hash） |
| max_names | **20**（与 v44 同） |
| category_weights | 五组各 **0.20**（锁死） |
| 筹码 | **完全不读**（同 v44；`BANNED_CHIP_COLUMNS` 同禁） |
| 持有/成本/基准 | 同 short_track 合同 |
| validation_start_date | **首次成功写出不可变 candidate snapshot 的交易日**（禁止写死 20260811，禁止历史回填充数） |
| input_universe | **必须等于** 当日 v44 已确认完整候选域（见 §5.3.3） |
| input_universe_hash | 与 v44 当日快照 **同一哈希**（对排序后 ts_code 集合稳定哈希） |
| 输出路径 | 与 control/v44 **隔离** 的 short_track book |

改动任一冻结字段 → 新 version + 重新 60 日。

#### 5.3.3 复用 v44 的原始组、输入与 **完全同一股票池**

组名与权重（与 `short_track_shadow.BALANCED_CATEGORY_NAMES` 一致）：

| 组 | 权重 | 原始信号方向（继承 v44 公式语义） |
|----|-----:|-----------------------------------|
| volatility_squeeze | 20% | 低 5d/20d 实现波动比等更优 |
| macd_early_strength | 20% | MACD 早期转强信号更优 |
| volume_turnover_stability | 20% | 量/换手波动更低更优 |
| relative_strength_neutralized | 20% | 5d/20d 收益合成后的相对强弱（中性化方式见下） |
| liquidity_risk_control | 20% | 流动性高、异常波动低更优 |

**股票池合同（v1.3 钉死，消解“悄悄改域”）：**

1. v45 **不得** 独立再跑一套与 v44 可能分叉的过滤；必须 **直接接收** 当日 v44 已经 `_require_balanced_frame` 确认的完整候选域（同一 feature frame / 同一 ts_code 集合）。  
2. v44 与 v45 快照均写入同一 `input_universe_hash`（及可选 `input_universe_size`）。  
3. 若两边 `ts_code` 集合不完全一致 → **v45 合同校验失败**（当日无合法 v45 输出）。  
4. 域内若存在 `circ_mv` 缺失、非有限或 **`circ_mv <= 0`**：v45 **整日失败**，**禁止** 删除该票后继续排名（避免相对 v44 缩域）。  
5. **禁止** 为修 v45 而改 v44 既有过滤条件（否则污染已在积累的 v44 版本）。  

原始特征与 v44 相同：`build_balanced_feature_frame` 列、≥21 日历史、`listing_days≥60`、非 ST/非停牌、`universe_flag>0`、禁止 proxy、禁止芯片列。

**不在 v45 第一版引入：** 新因子、筹码、regime 名额、动态权重、不同 TopN、不同股票池。

#### 5.3.4 截面处理流水线（唯一允许实现；无 “或”）

对每个交易日：

```text
步骤 0  股票池：加载当日 v44 已确认完整候选域 U
        - 校验 input_universe_hash 与 v44 快照一致
        - 若 U 中任一 circ_mv 非有限或 <= 0 → 整日失败（不缩域、不重归一）
        - 若 |U| < 20 → 整日失败（与 v44 fail-closed 一致）
步骤 1  原始组信号：在 U 上用与 v44 _balanced_component_scores 相同的原始公式
        得到 5 个 raw 组信号（尚未最终排序分）
步骤 2  异常值：对每个 raw 组信号做截面 MAD winsor（仅在 U 上）
        - 中心 = 截面 median
        - 尺度 = 截面 MAD；若 MAD=0 则跳过 winsor（保持原值）
        - 裁剪到 [median - 5*MAD, median + 5*MAD]（常数 5 冻结）
        - 诊断：记录每组被裁剪的股票数（可选，不进入晋级）
步骤 3  联合中性化（仅 relative_strength 路径）：
        - 在 U 全员上回归：raw ~ 1 + C(sw2021_l1_name) + log(circ_mv)
        - 取残差；circ_mv 已在步骤 0 保证 >0 且有限
        - 其余四组：winsor 后直接进入步骤 4（不做行业市值中性）
        - 禁止用 amount 代替 circ_mv
        - 禁止因回归失败而静默删票；回归无法完成 → 整日失败
步骤 4  残差/信号再标准化：截面 z-score（在 U 上）
        - z = (x - mean) / std；若 std=0 则 z=0
步骤 5  组内分数：将 z 映射到稳定序分
        - 按 z 升序（劣→优）对 ts_code 稳定排序（并列按 ts_code 字典序）
        - 赋分 linspace(0, 100, n)（与 v44 百分位赋分同区间）
        - 诊断：记录并列数量（可选）
步骤 6  合成：五组分数算术平均（等权 0.2）
步骤 7  排序：composite 降序，ts_code 升序并列；取 Top20
步骤 8  禁止：按票重归一、缩域、回填缺失、与 v44 不同 U 继续出数
```

**明确删除任选项：** MAD 或 1%–99%、rank 或 z、完整率模糊阈值、排除或降级二选一、行业字段二选一、单票剔除后继续排名。  
行业字段冻结为 **`sw2021_l1_name`**（与 v44 一致）。

## 6. AI 分析系统（严格降权）

### 6.1 定位

```text
AI = 证据解释器 + 冲突/风险标注器
≠ 选股器 / 硬否决器 / 综合评分器 / 价格生成器
```

- `rank_change = 0`  
- 同日证据 only  
- **禁止** 输出止损/支撑/压力/触发价等 **模型估算数字**（删除 `source=model_estimate`）  
- 若展示价格参考：必须由 **冻结规则公式** 从行情计算，标记 `source=rule_computed`；AI 只解释该数字含义  
- **禁止** display 综合分  

### 6.2 硬拦截：仅版本冻结的规则引擎

规则变更 = 升版 + 重计样本。LLM 不得覆盖规则结果。  
`observe_only` 日允许 20/20 观察。

### 6.3 输出与深度

- Tier A：结论摘要（≤ 系统动作上限）、量化依据转述、风险/冲突、数据完整性说明、points  
- Tier B：基本面/新闻等，源不可用则跳过  
- `ai_depth ∈ {shallow, standard, deep}`；shallow 可 full publish 但必须标深度  

### 6.4 质量门

- 不要求 advice 分化  
- 解释与规则动作上限一致  
- 禁止估算价格字段进入 ready 条件  

### 6.5 成本路由

规则卡全员 → 子集标准 LLM 解释 → 少量深度解释；失败回退规则卡。

## 7. 数据、运维与发布

### 7.1 三态状态机

| 字段 | 含义 |
|------|------|
| `selection_ok` | 主选股链合同通过 |
| `research_ok` | 影子/事件/研究；proxy 阻断 = **正确失败** |
| `publish_ok` | Pages/投递/git 结果通道 |

### 7.2 覆盖率与 NAV 语义

- 比率 ≤100%；单测钉死  
- 未到持有到期：`sample_trade_days=0` / 空 NAV **合法**  
- 告警：到期仍无结算或应有净值行缺失  
- 冻名单告警：连续 ≥3 **交易日** 完全相同才告警（排除节假日/重复发布误报）；只作文案与工程排查，不强制换股  

### 7.3 运行复现元数据（每个 snapshot/ledger）

必须保存：`code_git` 或 skill 版本、`strategy_version`、config hash、数据 asof/快照摘要、规则版本、`cs_pipeline`（若适用）。

### 7.4 发布链路

- SSL 重试；失败只影响 `publish_ok`  
- publish_guard + 合同校验 + 脱敏  

### 7.5 通知与 cron

- 修复 not-delivered  
- 简报含三态 + 唯一评价权威摘要；**不得**再贴旧 20 日 governance 结论当作现行晋级  

### 7.6 数据源

| 类型 | 政策 |
|------|------|
| 行情/PIT | 真源；fail-closed 优于假完整 |
| 流通市值 | 必须真实 `circ_mv`；禁用 amount 代理 |
| 筹码 | 仅 control 合同路径；v44/v45 禁用 |
| 新闻 | 无则跳过，不编造 |

### 7.7 GitHub 与本机边界（新增冻结）

| 通道 | 允许 | 禁止 |
|------|------|------|
| **代码库（GitHub repo）** | 架构、源代码、配置**模板**、测试、文档、运行脚本 | 原始行情库、完整 DB、缓存、历史 PIT 金库、含密钥日志 |
| **本机** | 全部数据湖、凭证、PIT、ledger 全量 | — |
| **GitHub Pages / 发布页** | 经白名单打包且脱敏的结果 JSON/静态页 | 本机路径、token、未合同校验产物 |
| **流程** | **代码更新** 与 **每日结果发布** 两个独立流水线 | 互相覆盖状态字段；用发布失败否定选股成功 |
