# Hermes 选股系统运行加固设计

**日期：** 2026-09-05
**状态：** 已批准实施（沿用 2026-09-05 审核中给出的修复建议）

## 目标

修复审核中确认的发布状态失真、夜间研究超时、失败告警缺失、运行依赖未纳入版本管理和 Hermes 执行账本恢复不可靠等问题，使系统在交易日能够稳定完成主流程、公开发布、盘后研究和失败通知。

本次不修改选股策略、风险阈值、仓位逻辑，也不启用自动交易；只加固运行、发布、监控和可恢复性。

## 已确认的问题

1. 公开网页已经部署成功，但公开产物中的 `run_manifest.published` 与 `system_verdict.pipeline_status.publish_ok` 仍为 `false`，使页面对外显示错误状态。
2. 盘后短轨研究生成完候选快照后，在结算阶段反复触发 120 万行价格索引的昂贵查找，并对同一批次重复计算基准收益，最终超过 600 秒。
3. 盘后研究配置中还有一个实际不执行任何工作的“评估”阶段，造成阶段含义与结果不一致。
4. 盘后研究任务失败已连续发生，但任务只写本机输出；21:05 的健康检查又早于 22:15 的盘后任务，因此无法及时通知。
5. 运行时依赖、发布门禁和回归测试中有文件未纳入版本管理，干净检出无法完整复现当前系统。
6. Hermes 执行账本修复尚未提交，且新闻网关仍运行旧进程。
7. 事件质量漂移任务每天执行，包括非交易日，造成无效周末运行。

## 设计决策

### 1. 公开发布状态在“实际部署产物”中盖章

推荐方案是在 Pages 部署工作流构建最终产物时显式传入 `--published-artifact`。构建脚本只在这个模式下，把输出目录内的清单盖为 `published=true`、`publish_state=published`，再据此生成一致的系统结论。源数据和普通本地构建仍保持 `false`，不会预先声称发布成功。

备选方案一是在推送后再创建第二个“已发布”提交。它会递归触发新的部署，且仍存在“状态提交本身是否已发布”的循环问题，因此不采用。

备选方案二是重新解释 `published` 字段为“准备发布”。这会破坏现有公开边界约定和下游含义，因此不采用。

最终产物只有在 Pages 部署成功后才会对外可见，所以用户能看到 `published=true` 时，产物本身已经被实际部署。

### 2. 盘后研究改用常数时间价格查询

把结算使用的价格表转换为以 `(证券代码, 交易日)` 为键的内存映射，避免 pandas 在第一次逐项查询时构建超大 MultiIndex 唯一性引擎。结算同一候选批次时，对相同入场日和退出日的基准收益只计算一次并复用。

短轨运行器本来就同时完成候选生成、结算和报告，因此删除后续无行为的 `shortTrackEvaluation` 阶段，保留一个真实、可解释的组合阶段。

### 3. 失败通知与任务时间对齐

盘后研究成功时保持安静，失败时保留清晰错误输出，并把 Hermes 投递目标改到现有选股系统通知渠道。这样失败会由任务本身直接通知，不再依赖早于它运行的健康检查。

事件质量漂移任务改为仅工作日运行。现有健康检查继续保留，作为主流程和数据新鲜度的独立防线。

### 4. 运行依赖完整纳入版本管理

提交生产发布门禁、复权价格回退模块及其回归测试，并把复权模块加入公开运行器同步白名单，确保内部仓库和公开镜像都能从干净检出启动。

只精确提交本次相关文件；工作区内其他历史修改和生成数据不纳入本次提交。

### 5. Hermes 恢复能力落地

提交已验证的稳定进程身份字段与误恢复防护，使用仓库规定的测试入口验证。确认没有活跃任务后重启仍使用旧代码的网关，并检查所有相关网关都已加载新版本。

历史执行记录保持原样，不反向改写旧状态。

## 数据流

交易日主流程先生成未发布的本地状态与页面源数据；Pages 工作流构建最终公开目录并在该目录内盖发布章；部署成功后该目录成为公开站点。盘后任务随后生成候选、一次性加载价格映射、完成结算与研究门禁；成功无通知，失败直接投递到选股通知渠道。

## 验证标准

- 新增测试先失败、修复后通过，完整选股脚本测试与端到端测试通过。
- 干净检出所需的运行文件全部被版本跟踪，公开镜像包含复权价格回退模块。
- Pages 实际部署完成后，线上清单为 `published=true`，线上系统结论为 `publish_ok=true`，提交链路一致。
- 使用 2026-09-04 的真实数据重跑短轨研究，在 600 秒内完成且结果为成功；完整盘后研究门禁通过。
- 人工故障演练能够产生一条失败通知，成功运行不产生噪声通知。
- Hermes 规定测试入口通过，相关网关重启后账本包含稳定进程身份字段。
- 至少观察后续两个交易日的主流程、发布和盘后任务；若出现异常，继续在同一任务中处理。

## 安全边界

- 不发出订单、不变更策略及风险参数。
- 不删除或覆盖用户现有的无关修改。
- 重启前确认没有相关活跃任务；发布前核对精确提交内容。
- 不伪造历史成功记录，所有成功声明以新运行和线上读取结果为准。
