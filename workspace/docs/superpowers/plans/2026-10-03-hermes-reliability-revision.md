## 2. 本轮实施范围（按要求顺序）

### P1 交易日历与日期一致性
1. 新增 `exchange_calendar.py`（仅标准库）：读取 `health/trading_calendar.json`，校验结构、来源、覆盖范围（from ≤ 今天 ≤ to）、生成时间不超过 45 天；返回 open / closed / error。**日历缺失或无效 = error，绝不当作休市。**
2. 业务入口门禁：晨判、盘前事件、午盘、主选股、AI 播报、收盘核算、夜间研究共 7 个 Hermes 入口在开头调用；休市日写入持久结果 `health/business_outcomes/<日期>/<任务>.json`（`skipped_market_closed`），静默退出 0；日历错误写 `calendar_error` 并非零退出告警。备份与数据新鲜度看门狗**不加门禁**，照常运行。
3. 日期语义分离，不做“改标签”：
   - `stage6_deploy_and_notify.py` 调用发布器时显式传入已锁定的交易日 `OPENCLAW_TARGET_TRADE_DATE`。
   - 午盘、晨判生成器把“当前交易时段日期”交给日历校验：非开市日直接报错（不回退到别的日期，不把旧数据标为今天）。晨判使用前一交易日收盘数据保持合法。
   - `stock_pipeline_gate.py` 自动推断的“今天”若日历为休市/无效则拒绝运行。

**验收**：休市日 7 个业务入口均有 `skipped_market_closed` 记录、无业务消息；日历文件缺失/损坏/过期/不覆盖今天时为 error 并告警；10/8 起主批次、策略、候选、裁决交易日一致；不存在以休市日为交易日的新记录。

### P2 最终发布检查具有约束力
1. 新增 `final_publication_gate.py`，在发布器生成全部内容之后、提交前运行，校验**将要发布的确切文件**：
   - 批次身份：`run_manifest` 的 run_id/trade_date 合法，且与调用方期望（stage6 传入的 RUN_ID/TRADE_DATE）一致。
   - 判定模式：与最近一次远端确认回执相同批次 = refresh（晨判/午盘刷新）；否则 = new_batch（新推荐名单）。
   - new_batch：裁决可解析、`final_action` 为对象且 `.action` 合法且 ≠ halt；`date_contract.passed=true`；无失败的硬阻断闸；裁决 run_id/决策日 = 批次；候选、策略、data.json 交易日 = 批次日且名单一致；manifest `validation_ok/publish_ready=true`，full 模式要求同日 AI 完整；交易日为开市日。
   - refresh：裁决仍须可解析；候选名单（交易日+代码集合）必须与已发布 HEAD 一致，刷新不能换名单；halt 状态可作为标注清楚的状态更新发布，但不得冒充新选股。
   - 任何缺失、畸形、过期、不一致 → 拒绝发布（非零退出），写 `health/publication_validation.json`。
2. 发布器改动：保存调用方期望身份；把 `publish_guard` 生成移到最终检查之前；最终检查放在幂等闸之前（幂等“跳过并写回执”路径也必须先通过检查）；提交后记录已验证提交；`fetch + rebase` 后若发布路径内容与已验证提交不同则中止（需重新验证），不强推、不丢弃本地无关改动（沿用 stash/恢复）。
3. 播报器（20:00）：读取已发布裁决，new_batch halt/畸形/批次不一致不播报；要求本批次的 `publication_validation` 通过且回执 SHA 一致；按“交易日+名单指纹”去重，同批次不重复播报；回执改为如实的 `handed_to_hermes_stdout`（交由 Hermes 投递），不再写“已送达”。

**验收**：隔离夹具中注入 halt、裁决不可读、`final_action` 非对象、日期不一致、run_id 不一致、刷新换名单、rebase 后内容变化，均拒绝发布/播报；正常 observe_only 批次可发布；同一交易日重跑不重复播报。

### P3 用真实依赖协调流程
- 保留现有锁目录、发布锁、发布回执、`production_release_gate` 等显式状态；不使用 `context_from`。
- 修正 Stage1 预算：由编排器向 Stage1 传入不超过阶段超时减 180 秒的最长等待，使重试在阶段超时前干净结束并写终态，而不是被强杀。
- 收盘核算输出当日真实业务状态（选股/发布/播报/跳过），上游失败时照常报告；写 `health/daily_business_status/<日期>.json`。备份、看门狗不依赖选股成功。

**验收**：Stage1 终态记录必有明确 terminal 原因；收盘核算在上游失败日输出失败而非“✅”。

### P4 数据源冗余（核验，不重复实现）
- 逐项核验 9/30 修复是否在生产代码中，并形成数据集 × 提供方能力矩阵（字段、日期、覆盖、复权、来源、已知限制）。
- 不新增替代源、不放宽任何守门；Promax 因子仍标为“不合格备用”。

**验收**：矩阵与核验结果存档；不改变任何数据守门逻辑。

### P5 研究输入处理
- 短线冻结输入与公共 PIT 副本比较：保持精确比较；仅当差异**全部**位于 `name` 列，且每处差异只是新股上市标记 `N`/`C` 前缀增删、ST/*ST/退市等风险标记不变时，判为展示性变更：继续使用原冻结文件，并写入带来源和校验和的修订记录（新版本，不覆盖旧文件）。其它任何差异仍拒绝，并写结构化差异报告。
- 盘前事件：不可变文件已存在且新取数不同 → 把新内容另存为带校验和的修订版本与来源记录，原文件不动（现状是静默丢弃）。
- 回归测试：`N力勤资源`→`力勤资源` 通过；`ST`/`*ST` 变化、数值修订、行集变化均拒绝。保持 600 秒预算与各组件独立结果。

### P6 状态与通知
- 区分并持久记录：选股成功、发布成功、可选研究、业务跳过、通知结果。
- 告警去重：新增 `stock_alert_policy.py`，同一任务同一失败签名重复出现时只发一行“仍未恢复（第 N 次）”，恢复时发一次“已恢复”。
- 不改频道、不改代理、不关 TLS；Hermes 自身对未确认（ack）故障的每次失败提示保持不变。
- 看门狗成功心跳追加到 `health/watchdog_heartbeats.jsonl`，不发每日绿色消息。

### P7 策略评估（独立工作流，本轮只做报告）
- 在数据允许范围内复算：版本拆分、去回填 AI、重复标的、非重叠窗口；基准与超额需读取 parquet 价格面板，只能在 Mac 上执行，本轮列为待办，不做结论。
- 不推广新因子、不制造买入建议、不改观察权限。
